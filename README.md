# 評量作答紀錄

這是可直接部署到靜態網站主機的單頁網頁，沒有建置步驟或額外套件。

## 網頁功能

- 從學生名單試算表載入班級座號。
- 從題目試算表 `draft` 讀取 `Exam_ID`、`Question_No`、`狀態`；只顯示狀態為 `A` 的考卷，依資料最後出現位置由新到舊列出最新 4 份。
- 步驟一、二、三在同一個畫面；班級座號和考卷使用下拉選單。
- 題號依英文字首分組：Q 為選擇題、F 為填充題、W 為計算題；各題型分開換行，每列最多 10 題。
- 逐題點選 1（答對）或 0（答錯）。
- 每列最多 10 題；題目較多時會自動換列。
- Apps Script 寫入端使用 ReDraft 工作表欄位：`學生班級座號`、`Exam_ID`、`Question_No`、`對錯紀錄`。
- 教師管理頁可編修 ReDraft 草稿；題型依題號英文字首即時推算，確認後寫入 `Record`，驗證成功後清除 ReDraft 資料列。若 `Record` 不存在，程式會建立工作表及標題列。
- 同一學生、考卷與題號再次送出時更新既有紀錄，避免重複列。

## 試算表讀取方式

網頁以 Google Visualization 試算表資料來源讀取公開唯讀資料，不需要 Google Sheets API 金鑰。資料仍由瀏覽器直接向 Google 讀取。依 Google 文件，受限制的試算表需要 OAuth 等授權；不要把服務帳戶金鑰或 OAuth 機密放進前端網頁。

目前設定的工作表：

- 學生名單：工作表 gid `0`，取第一欄的班級座號。
- 題目資料：`draft` 工作表 gid `2028107386`，依欄位 `Exam_ID`、`Question_No`、`狀態` 整理考卷與題數，只採用狀態 `A` 的資料。

如更換工作表分頁或欄位名稱，請同步更新 `index.html` 的 `SOURCES` 與欄位辨識邏輯。

## 部署前的存取與隱私檢查

已確認預計公開部署，任何網站訪客都能查看目前表格中的班級座號清單。公開網站上的瀏覽器程式必須取得學生名單，因此訪客也能檢視來源資料。不要在前端加入 API 金鑰或服務帳戶憑證。

`Code.gs` 提供 Apps Script 寫入及教師管理程式。請在 Apps Script「專案設定 → 指令碼屬性」新增 `TEACHER_ACCESS_CODE`，值為教師使用的辨識碼，再部署網頁應用程式。`ReDraft` 使用四欄：`學生班級座號`、`Exam_ID`、`Question_No`、`對錯紀錄`。`Record` 使用五欄：`學生班級座號`、`Exam_ID`、`Question_Type`、`Question_No`、`對錯紀錄`；Q、F、W 題號分別推算為選擇題、填充題、計算題。教師確認後會先寫入並驗證 Record，才清除 ReDraft 資料列。
